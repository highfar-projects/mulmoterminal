# 5.0.1 — 終わったセッションが、どのエージェントだったかを言う

**5.0.1 時点のスナップショットです（2026-09-18 リリース）。** アプリが進めば古くなります — それは
織り込み済みで、生きているリファレンスは各節からリンクしているガイドのほうです。

**設定は要りません。** 上げればそうなります:

```bash
npx mulmoterminal@latest
```

---

## 何が間違っていたか {#what-was-wrong}

[会話ペイン](v5.0.0.html)が読めるのは今のところ 4 つ（Claude / Codex / Cursor / Copilot）で、
残りの 3 つについてはその旨を出します。それが役に立つ答えだからです:

> このエージェントの会話は、まだここで読めない場所にあります。

ところがその判定は、セルが**何を動かしているか**を聞いて行っていました — 生きているプロセスか、
tmux が報告するペインのコマンドか。セッションが終われば両方とも消えるので、その瞬間から
**grok** / **muse** / **Antigravity** のセッションには別の文言が出ていました:

> このセッションの transcript には、まだ何も書かれていません。

これは別のことを言っていて、しかも事実と違います。会話は存在していて、こちらが読めないだけです。
スマホの会話ビューも同じ resolver を通るので、同じ表示になっていました。

## 何を変えたか {#what-changed}

プロセスではなく、**エージェント自身の記録**に聞くようにしました。聞くのは、どの reader も
transcript を見つけられず、かつプロセスが答えられなかったときだけです。Antigravity と muse は
MulmoTerminal が既に持っている「どのセッションがどの会話を動かしているか」のログから、grok は
セッションのディレクトリの有無から答えます（grok の会話は、セッションが持っている id そのもので
並んでいるため）。

生きているセルには影響しません。従来どおり自分のプロセスから答えるので、これらの参照は 1 つも
走りません。

## 修正が入ったかどうかの見分け方 {#how-to-tell}

**grok** / **muse** / **Antigravity** の、**終了済み**のセッションが必要です（セルはグリッドに
残っていて、エージェントはもう動いていない状態）。

1. そのセルを拡大して、**Conversation** ペインを開く
2. 5.0.1 より前: 「このセッションの transcript には、まだ何も書かれていません」
3. 5.0.1 から: 「このエージェントの会話は、まだここで読めない場所にあります」

Claude / Codex / Cursor / Copilot しか使っていない場合、見える変化はありません。この 4 つは
transcript から読んでいて、元から影響を受けていませんでした。

その 3 つの会話を**実際に読めるようにする**のは別の作業で、
[#1822](https://github.com/receptron/mulmoterminal/issues/1822) で追っています。このリリースは
それまでの間どちらの文言が出るか、という話です。
