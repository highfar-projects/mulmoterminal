# 4.23.0 — cursor のセルが、グリッドの他のセルに追いつく

**4.23.0 時点のスナップショットです（2026-09-14 リリース）。** アプリが進めば古くなります — それは
織り込み済みで、生きているリファレンスは各節からリンクしているガイドのほうです。

cursor は 4.22.0 で「動く・状態を報告できる」状態になりましたが、他のセルが持っていて cursor だけ
持っていないものが 3 つありました。このリリースでその 3 つを塞ぎます。**GUI ツール**、**トークン
バッジ**、そして**そのセルが直前に何と答えたか** — 完了通知が引用し、handoff が別のセルに渡すものです。

**設定が要るのは最初の 1 つだけ**で、それも既にご存じのスイッチです。

---

## cursor のセルに GUI ツールを持たせる {#gui-tools}

空きセルのランチャにある **Canvas / Workspace data / External accounts** のスイッチが、cursor にも
届くようになりました。前のリリースまでは「まだ何も入りません」という一行に置き換わっていた場所です。

1. 空きセルのランチャで、Agent Picker の **Cursor** を選びます。
2. **WORKING DIRECTORY** にディレクトリを入れます（ワークスペースなら **WORKSPACE** チップ）。
3. 必要なものを ON にします。`presentDocument`・`presentChart`・`presentHtml`・`presentForm` を
   持ってくるのは **Canvas**（`render`）です。
4. **セッションを起動し直します。** スイッチは*ディレクトリ*への登録なので、既に動いている
   セッションには届きません。

**効いたかの確かめ方**（軽い順に 3 つ）:

- `<そのディレクトリ>/.cursor/mcp.json` に `mulmoterminal-render` サーバが入っています。書いたのは
  MulmoTerminal で、あなたがそのファイルに書いていた内容はそのままです。
- そのディレクトリで `cursor-agent mcp list` を実行すると `mulmoterminal-render: ready` と出ます。
- セルの中で「`mulmoterminal-render` サーバのツール名を挙げて」と頼むと、`presentDocument`・
  `presentChart`・`presentHtml`・`presentForm` と ShapeScript 系が返ります。

**`ready` が大事な理由。** cursor は**承認していない** MCP サーバを読み込まず、しかも読み飛ばしたことを
何も言いません（セルからは「MCP サーバが無い」としか見えません）。MulmoTerminal は自分が書いた項目
だけをセル起動時に承認するので普段は意識不要ですが、もしセルが「サーバが無い」と言ったら、承認が
原因かどうかを教えてくれるのがこのコマンドです。

**ファイルは `git status` に出しません** — ただし MulmoTerminal が作った場合だけです。`.cursor/mcp.json`
が元からリポジトリにあったなら、それはあなたのファイルです。記述はそのまま残り、`git status` からも
隠しません。

[Antigravity・Grok・Muse・Cursor はどこでも登録が要る](basics.html#antigravity-gui-tools)

## cursor のセルのトークンバッジ {#token-badge}

設定は不要です。cursor のセルが最初のターンを終えると、他のセルと同じ `⇡ 入力 ⇣ 出力` のバッジが
ヘッダーに出ます。

**読む前に知っておくとよいことが 2 つ:**

- **数え始めるのは、そのサーバでセルが動き出してからです。** cursor はトークン数をどのファイルにも
  書かず、ターン終了のフックに載せて送ってくるだけなので、MulmoTerminal はそれをメモリで足して
  います。サーバを再起動するとカウントは次のターンから数え直しになり、再開した会話は次のターンが
  終わるまで何も出ません。読み戻せない場所の数字を持ち越すより、こちらが正直な答えです。
- **`ctx %` はまだ出ません。原因は cursor の `model` フィールドです。** Auto のセッションでは cursor が
  モデル名を `default` と報告します。これはモデル ID ではなく、% の計算にはモデルごとの context
  window が要るためです。モデルを固定すれば（`CURSOR_MODEL`、またはランチャのモデル選択）、他に何も
  しなくても % が出ます。

→ [セルの読み方](basics.html)

## そのセルが直前に答えた内容 {#last-turn}

これも設定不要です。cursor のセルの終わったターンが返答を持つようになり、これまで cursor では空だった
3 か所が埋まります。

- **完了通知**（およびスマホへの push）が、エージェントが実際に言ったことを引用します
- **handoff**（あるセルの直近のやり取りを別のセルに渡す機能）が返答を運びます
- **round table** の席が、自分の結論を出します

**渡すのは「結論」であって「前置き」ではありません。** 「まずファイルを読みます」と言ってから 1 分
作業したターンは、最後に出した答えのほうを渡します。この区別がこの機能の実装のほぼ全てです — エージ
ェントがターン中に書く文章の大半はナレーションで、round table の席に前置きを渡してしまう不具合は
このプロジェクトで一度起きています。

## ガイドの GUI ツールの説明を書き直しました {#guide}

機能ではありませんが、ガイドを読むと気づく変更です。`basics`・`config`・`glossary`・FAQ が GUI ツールの
入り方を「Claude / Codex 対 Antigravity / Grok」の **2 択**として説明していました。Muse が入った 4.7.0
の時点で既に誤りで、4.22.0 以降は二重に誤りでした。実際には**経路は 4 つ**で、ガイドもそう書いています。
