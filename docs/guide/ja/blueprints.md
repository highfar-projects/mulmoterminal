# 設計図（試験中）— 試してくれる人向けの案内
{: .no_toc }

「設計図」は、作りたいアプリを聞き取って仕様書にまとめ、その仕様書から工程ごとに Claude Code が組み立てていく機能です。アプリだけでなく、文書も扱えます（規約をつくる・書く・整える・読み解く・確かめる・尋ねる。[文書を扱う](#documents)）。人が決めること（仕様の確認、費用のかかる操作、公開）だけ止まって聞き、あとは最後まで自動で進みます。

> **試験中です。** MulmoTerminal 6.5.0 から入っていますが、見た目も中身も変わっていく途中です。

## 用意するもの

| | 必要なもの |
|---|---|
| 全員 | Node.js 22.13 以上、`yarn`、ログイン済みの Claude Code（`claude` が動くこと）、git |
| Firebase で試す人だけ | Google アカウント、支払い方法を登録できる Google Cloud の請求先アカウント、`firebase`（Firebase CLI）、`gcloud`、JDK 21 以上（macOS なら `brew install openjdk@21` で足ります） |

まずはローカル（Firebase なし）で試してください。こちらは自分の PC の中だけで完結し、費用もクラウドの設定も要りません。

> **Claude の利用量について**: 1 回のビルドは工程ごとに Claude Code のセッションを起こすので、ふつうにチャットするよりまとまった量を使います。

## 動かす

```bash
npx mulmoterminal@latest
```

ブラウザで `http://localhost:34567` を開きます。上のバーの「その他の機能」メニュー（`widgets` アイコン）に「設計図」があれば準備完了です（`npx mulmoterminal --version` が 6.5.0 以上であること）。

- 設計図を動かせるのは、**1 台の PC で 1 つの MulmoTerminal だけ**です。MulmoTerminal を 2 つ同時に起こすと、あとから起こした方は一覧を見ることはできても、操作すると「このマシンの設計図は、ポート … の MulmoTerminal が動かしています」と断られます。
- 各工程のエージェントは、いつものグリッドには出てきません。何をしているかは設計図の画面に表示されます。

## 作業用フォルダを信頼しておく {#trust}

エージェントは誰も見ていないところで動くので、Claude Code の「このフォルダを信頼しますか？」で止まると先へ進めません。そのため、**信頼済みのフォルダの中**でしか始められないようになっています。一度だけ次の準備をしてください。

1. 試し用の親フォルダを作ります（例: `mkdir ~/blueprint-trials`）。
2. そのフォルダで `claude` を起動し、信頼するかを聞かれたら「はい」を選んで、すぐ終了します。
3. 以後は、ビルドのたびにこの中のフォルダを使います。まだ無いフォルダ名（例: `~/blueprint-trials/library`）を入れれば、「始める」を押したときに作られます。新しいフォルダは親の信頼を引き継ぐので、改めて信頼する必要はありません。`~` はホームフォルダのことで、欄にそのまま入れて構いません（Windows なら `~\blueprint-trials\library` でも `C:\Users\<名前>\blueprint-trials\library` でも同じです）。

> **作ったフォルダで `git init` はしないでください**。git のリポジトリになったフォルダは親の信頼を引き継がなくなり、途中の工程で止まります。git で管理したいときは、ビルドが終わってからにしてください。

## 最初の一回: 「おうち図書館」

家にある本と、誰に貸しているかを記録する小さなアプリを、自分の PC の中に作ります。

1. 「その他の機能」→「設計図」→「新しく作る」を開きます。
2. 「例から始める」で **おうち図書館** の「この例で始める」を押します。土台（ローカル）、作るものの種類（自由に作る）と質問への答えが入ります。
3. 「プロジェクトのフォルダ」には、最近のビルドの隣など信頼済みの場所に、この例のための新しいフォルダが入ります。入らなかったとき（初めてのときなど）は `~/blueprint-trials/library` のように入れます。そのまま「始める」を押すと、フォルダが作られて始まります。
4. 最初の工程で仕様書ができると、**仕様書の画面**で止まります。ここがいちばん大事なところです。
   - 仕様書を読み、「決めていないこと」が残っていれば確認します。
   - 変えたいことがあれば、下の欄に書いて送ります（例: 「本の削除もできるようにして」）。エージェントが仕様書を直して返事をします。
   - 納得したら「承認する」を押します。
5. あとは工程が順に進みます。作業中の工程では、エージェントが何をしているかと経過時間が表示されます。
   - 「質問が届いています」と出たら、答えを書いて「送る」を押します。
   - 工程が止まったら、「判定の結果」を読んで「もう一度」を押せます。
6. 「すべての工程が完了しました」と出たら終わりです。フォルダの `README.md` に、起動のしかた（`yarn start`）とデータの置き場所が書かれています。起動して、実際に使ってみてください。

## 試してほしいこと

できた範囲で構いません。どれを試したかも教えてください。

**基本の流れ**
- [ ] おうち図書館を最後まで作り、できたアプリが動く
- [ ] 仕様書の画面で会話をして、仕様書が直る（何往復かしてみる）
- [ ] ほかの例（家計簿・チームのタスクボード・見積書づくり）を一つ作る
- [ ] 例を使わず「自由に作る」で、自分の作りたいものを一つ作る

**止まり方・戻り方**
- [ ] 質問に答えると先へ進む
- [ ] 承認のところで「やめる」を押すと、そこで止まる
- [ ] 作業中に MulmoTerminal を止めて起こし直すと、その工程をやり直して続く
- [ ] 画面の案内（質問の手順）だけで、迷わず操作できる

### 文書を扱う {#documents}

土台に「文書のフォルダ」を選ぶと、アプリの代わりに文書を扱います。文章の検査には chaff を使います（自動で取ってくるので準備は要りません）。文書を入れたフォルダを信頼済みの親フォルダの中に作り、「作るものの種類」で次のどれかを選びます。

手元に文書が無くても試せます。「例から始める」に文書の例（業務委託契約書を読み解く、旅程表を確かめる、経費精算の手引きに尋ねる、社内のお知らせを整える、社内の手続きの文章から規約をつくる、新しく入った人向けの手引きを書く）があり、選ぶと新しいフォルダが入るので、そのまま始めると、見本の文書がそのフォルダに置かれます。既にあるフォルダを選んだ場合、同じ名前の別のファイルがあると始まりません。終わると、設計図の画面に報告（見つけたこと・確かめたこと・残したこと）がそのまま表示されます。

- [ ] 「文書を確かめる」: 旅程表や見積書を入れると、曜日の誤り、予定の順番の入れ違いや時間の重なり、合計が内訳の和になっていないところを、機械が見つけて報告する。わざと曜日や合計を間違えた旅程で、その誤りが報告に出る
- [ ] 「文書を読み解く」: 契約書や規程の、存在しない条への参照や食い違いが、原文の引用付きで出る。chaff が間違えた所（読み解いて退けた指摘、chaff が見逃した構造の問題）は、chaff への報告の下書きとして `.blueprint/chaff-feedback/` に残る。下書きは何も送らないので、読んでから送るかを決める
- [ ] 「文書に尋ねる」: 質問に、文書のどこに書いてあるかを添えて答える

**Firebase（慣れている人だけ）**

Firebase の土台は、開発用とそれとは別の本番用、2 つの Firebase プロジェクトを使い、従量課金（Blaze）への切り替えも必要です。いまのところ確かめているのは**開発用への公開まで**です。本番への公開の承認はしないでください。

- [ ] 「ミニ SNS」の例で、開発用に公開されたアプリに Google でログインできる
- [ ] 土台 Firebase・種類「社内向け業務アプリ」の「稟議」の例で、会社のドメイン以外のアカウントが断られ、その画面がわかりやすい
- [ ] コンソールでの操作を頼まれたとき、質問に書かれた手順だけでできる

## 困ったとき

| 起きたこと | 見るところ |
|---|---|
| 「始める」で「Claude Code がまだ … を信頼していません」と断られる | [作業用フォルダを信頼しておく](#trust) をもう一度。フォルダが git のリポジトリになっていないかも確認 |
| 「… がありません。新しいフォルダは、既にあるフォルダの中にだけ作れます」と断られる | 作るのは最後の一段だけです。途中のフォルダ（親）を先に作るか、既にあるフォルダの中を指定します |
| 工程が止まった | 「判定の結果」に理由が出ます。「もう一度」でやり直せます |
| 操作すると「このマシンの設計図は、ポート … の MulmoTerminal が動かしています」と断られる | この PC で MulmoTerminal がほかにも動いています。そちらを使うか、止めてください |
| ビルドの記録を消したい | `~/.mulmoterminal/blueprints/runs/` の中の、そのビルドのフォルダを消します。作ったアプリのフォルダはそのまま残ります |

## 報告のしかた

うまくいったことも、いかなかったことも [issue #2246](https://github.com/receptron/mulmoterminal/issues/2246) にコメントしてください。次があると助かります。

- MulmoTerminal のバージョン（`npx mulmoterminal --version` の結果）
- 土台・作るものの種類・使った例（自分で書いたなら、その内容のあらまし）
- 何をしたら、何が起きたか。期待していたことは何か
- 画面のスクリーンショット（ビルドの画面の URL `http://localhost:34567/blueprints/…` も）
- 止まった工程の「判定の結果」の文言

> スクリーンショットや文言に、メールアドレス・プロジェクト ID・フォルダのパスなど見せたくないものが写っていたら、隠してから貼ってください。

## わかっている制限

- Firebase の本番への公開（`protect` 以降の工程）は、まだ実際には確かめていません。
- コンソールでの操作の手順は、Firebase のコンソールの表示が変わると合わなくなることがあります。合わなかったら、どの画面で何が違ったかを教えてください。
- 公開後の確認は「画面が真っ白でないこと」までで、読み込み中のまま止まる不具合は見逃すことがあります。
- 「マーケット」（外からパックを取り込む画面）は試作です。公式の一覧はまだありません。
