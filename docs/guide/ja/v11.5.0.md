# 11.5.0 — 使用量ゲージがどこから起動しても出る

**11.5.0 時点（2026-10-28 リリース）のスナップショットです。** アプリが変わるにつれて古くなります。
それは想定どおりで、最新の説明は各節からリンクしているガイドにあります。

## 新機能

### ボードのカードに Codex の最新の判定

試験的な GitHub ボード（ツールバーの GitHub マーク → **ボードを開く（実験的）**）で、スレッドに
`CODEX VERDICT:` のコメント（`codex-cross-review` のループが投稿するもの）があるプルリクエストは、カードに
**Codex 2: LGTM** や **Codex 2: 修正要求** と出るようになりました。数字はこれまでの判定の回数です
（[#3197](https://github.com/receptron/mulmoterminal/pull/3197)）。

色（緑か赤）が付くのは、**判定がいまブランチにある push を名指ししているとき**だけです。判定の行は
`CODEX VERDICT: LGTM (head <sha>)` という形で、その sha が一致している必要があります。前の push についての
判定は薄く描かれ、隣に **古い push 向け** と出ます。push を名指ししていない判定は **push 未指定** です。
数えるのはリポジトリの所有者・メンバー・コラボレーターの判定だけで、マージ済みのカードには出ません。
レビューの回数と列は以前のままです。設定は要りません。ボードを開き、Codex のレビューを受けたことのある
開いているプルリクエストを見てください。詳しくは：[GitHub](github.html)。

## 画面の変化

- **Codex の再開一覧に、題名の無い「Guardian review」の行が出なくなりました**
  （[#3199](https://github.com/receptron/mulmoterminal/pull/3199)）。Codex は自分のツール呼び出しの審査や
  記憶の整理を、同じフォルダの別の会話として保存します。起動画面の「このフォルダの Codex の会話を再開」の
  一覧にそれが混ざっていました。いまは人が始めた会話だけが並びます。確かめ方：Codex を使ったことのある
  フォルダで起動画面を開き、再開の一覧を見てください。題名の無い行が消えています。
- **Windows の psmux 3.4.0 で、新しいセルの先頭に設定の警告が出なくなりました**
  （[#3205](https://github.com/receptron/mulmoterminal/pull/3205)）。どのセルも 1 行目が
  `psmux: 1 config warning(s): … unknown option 'terminal-features'` でした。その行は tmux にクリックできる
  リンクを通してもらうための指定で、psmux は指定なしでも通すので、psmux の設定からは外しました。サーバーを
  一度再起動して新しいセルを開くと、その行は出ません。
- **使用量ゲージにカーソルを重ねた文言が、フォルダを名指しします。** Claude の数字が、確認が Claude Code の
  信頼プロンプトで止まっているために出ていないとき、どのフォルダで `claude` を実行すればよいかを書くように
  なりました（[#3203](https://github.com/receptron/mulmoterminal/pull/3203)）。11.5.0 ではこの文言自体を
  ほとんど見ないはずです。[見えない変化](#usage-probe)を見てください。

## 見えない変化

### Claude の使用量ゲージが、ホームを含めどのフォルダから起動しても出る {#usage-probe}

**何が壊れていたか。** グリッドの上の段の Claude の 5h / 7d の数字は、隠れた `claude` のセッションが小さな
質問を 1 つして取ってきます。これまでそれはワークスペース、つまり `npx mulmoterminal` を打ったフォルダで
動いていました。ホームディレクトリで起動すると、そこは Claude Code が信頼の答えを保存しない唯一のフォルダ
なので、隠れたセッションは毎回「このフォルダを信頼しますか」で止まり、上の段には `claude usage n/a` と出て、
カーソルを重ねた文言どおりに承認しても何も変わりませんでした
（[#3200](https://github.com/receptron/mulmoterminal/issues/3200)）。

**何が変わったか。** 確認は、どこから起動しても MulmoTerminal 専用のフォルダ `~/.mulmoterminal/probe` で
動くようになりました（[#3203](https://github.com/receptron/mulmoterminal/pull/3203)）。そして、そのフォルダで
手で `claude` を動かす人はいないので、MulmoTerminal がそのフォルダの信頼の答えを、確認を動かすログイン
（いつものログインと、各[2 つ目の契約](accounts.html)）の Claude Code の設定に、最初の確認の前に自分で
書き込みます（[#3207](https://github.com/receptron/mulmoterminal/pull/3207)）。フォルダは空で MulmoTerminal の
ものなので、信頼しても Claude Code が読むものは増えません。書き込みは一度だけで、Claude Code 自身の保存に
たまたま上書きされたときは、次の確認で書き直します。

**することはありません。** 直っているかの確かめ方：ホームディレクトリで MulmoTerminal を起動してグリッドを
開くと、1〜2 分のうちに上の段に Claude の `5h` / `7d` の数字が出ます。それでも `claude usage n/a` のままで、
カーソルを重ねた文言が信頼プロンプトを挙げるときは、答えを書けなかったときです。そのログインで `claude` を
一度も動かしていなければ、設定ファイルがまだありません。その場合は文言どおりに一度だけ、
`~/.mulmoterminal/probe` で `claude` を実行して（2 つ目の契約なら、**Working directory** に
`~/.mulmoterminal/probe` と入れてそのアカウントのセルを起動して）プロンプトを承認してください。詳しくは：
[設定](config.html)の `usageGauge`、[2 つ目の契約](accounts.html)。

### Windows: npm で入れた Codex が psmux のセルで起動する

Windows の psmux で、同じマシンの Claude のセルは動くのに、新しい Codex のセルが
`psmux: can't find session: mulmoterminal__mt-…` と出てすぐ終わることがありました
（[#3202](https://github.com/receptron/mulmoterminal/pull/3202)）。違いは入れ方です。`claude.exe` は psmux が
そのまま起動できるプログラムですが、npm で入れた `codex` は `.cmd` のスクリプトで、psmux は起動できません。
MulmoTerminal は、psmux を使わないときと同じように、psmux のペインの中でもそのスクリプトを `cmd.exe` 経由で
起動するようになりました。することはありません。Codex のセルが開いて、そのまま使えます。
