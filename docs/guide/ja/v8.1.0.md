# 8.1.0 — 設計図の作業で変わったところが見え、試せる例が増えた

**8.1.0（2026-10-01 公開）時点のスナップショットです。** アプリが変わるにつれて古くなりますが、
それは想定どおりです。最新の説明は、各節から張ったガイドを見てください。

設定の必要はありません。今回の変更はすべて **設計図**（ツールバーの設計図の画面）の文書の作業です。

## 新機能

### 作業のあとで、元の文書との違いを見る

- 文書の作業が終わると、完了画面の報告の下に、作業が元を取っておいた文書（`.blueprint/originals/`）ごとに
  「元の文書」と「今の文書」の比較が出ます（[#2793](https://github.com/receptron/mulmoterminal/pull/2793)）。
  どこをどう直したかが、前後の文と一緒にその場で見られます。
- 「文書を読み解く」で 「直し方の案まで作る」 を選んだときに文書の横にできる案（`<名前>.proposed<拡張子>`）も、
  元の文書と比べて出ます（[#2795](https://github.com/receptron/mulmoterminal/pull/2795)）。
- この比較は、明るいテーマや自作のテーマでもアプリの色に合わせて出ます（[#2797](https://github.com/receptron/mulmoterminal/pull/2797)）。

### 続けて「文書を整える」

- 「文書を整える」で、棚に上げた指摘も直せるようになりました（[#2781](https://github.com/receptron/mulmoterminal/pull/2781)）。
  「棚上げした指摘も直しますか」 に 「棚上げした指摘も直す」 と答えると、chaff を入れたときに棚に上げた指摘まで直します。
- 「文書のフォルダに chaff を入れる」 の完了画面から、同じ場所を 「文書を整える」 で続けられます
  （[#2783](https://github.com/receptron/mulmoterminal/pull/2783)）。
- 「用語をそろえる」 の完了画面から、同じ文書を 「文書を整える」 で続けられます
  （[#2765](https://github.com/receptron/mulmoterminal/pull/2765)）。

### 作業が見るところが増えた

- 「文書を整える」 は、仕様書と README・技術文書を、読む人が必要とすることの観点でも見ます
  （[#2779](https://github.com/receptron/mulmoterminal/pull/2779)）。
- 「文書を確かめる」 は、合計だけでなく、単価 × 数量と税額も確かめます（[#2763](https://github.com/receptron/mulmoterminal/pull/2763)）。

### 自分の文書が無くても試せる例

新しい作業のフォームの 「例から始める」 に、次の例が加わりました。

- 「規程を規程として整える」（[#2755](https://github.com/receptron/mulmoterminal/pull/2755)）
- 「英語のブログ記事を整える」 — 文書は英語のまま、報告は自分の言語で返ります（[#2773](https://github.com/receptron/mulmoterminal/pull/2773)）
- 「出張旅費規程の改定を比べる」（[#2757](https://github.com/receptron/mulmoterminal/pull/2757)）
- 「検討報告を部長向けに要約する」（[#2759](https://github.com/receptron/mulmoterminal/pull/2759)）
- 「見積書を確かめる」（[#2761](https://github.com/receptron/mulmoterminal/pull/2761)）
- 「ネットショップの利用規約を読み解く」（[#2767](https://github.com/receptron/mulmoterminal/pull/2767)）
- 「休暇の規程と手引きに尋ねる」 — 食い違う二つの文書に尋ねます（[#2769](https://github.com/receptron/mulmoterminal/pull/2769)）

詳しくは [設計図のガイド](blueprints.html)。

## 画面の変化

- 新しい作業のフォームの例は、作業ごとに一つだけ出て、残りは 「ほかの例を見る」 で開きます
  （[#2785](https://github.com/receptron/mulmoterminal/pull/2785)）。例が多くて作業の選択が下に埋もれていたためです。
- 文書の作業は、よく使うものから並びます（[#2787](https://github.com/receptron/mulmoterminal/pull/2787)）。
- 「文書を整える」 の報告で、書いた人に確かめてほしいことが、整えたものの直後に来ます
  （[#2789](https://github.com/receptron/mulmoterminal/pull/2789)）。
- 「規約をつくる」 の言語と厳しさの質問に、よく選ばれる答えが最初から入っています
  （[#2771](https://github.com/receptron/mulmoterminal/pull/2771)）。

## 見えない変化

- 「用語をそろえる」 が chaff.yaml を作るとき、種類の違う文書にはそれぞれの種類を書きます
  （[#2775](https://github.com/receptron/mulmoterminal/pull/2775)）。規程と手引きが両方とも規程として測られなくなりました。
- chaff.yaml だけで足りるときに、「文書を整える」 の報告が STYLE.md が無いと書かなくなりました
  （[#2777](https://github.com/receptron/mulmoterminal/pull/2777)）。
- 文書の作業は chaffjs 0.17 で動きます（[#2791](https://github.com/receptron/mulmoterminal/pull/2791)）。

どれも、何もしなくてよい変化です。
