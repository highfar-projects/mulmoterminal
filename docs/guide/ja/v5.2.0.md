# 5.2.0 — ロスターをドラッグ、そして全エージェントに要約

**5.2.0 時点（2026-09-18 リリース）のスナップショットです。** アプリが進むにつれて内容は古くなり
ます。それは想定どおりで、常に最新なのは各節からリンクしているガイド本体です。

3つ入っています。1つ目は設定が1つ、2つ目は設定不要、3つ目は**すでにお使いの設定を直す必要がある
かもしれません**。

---

## 1. ロスターの行をドラッグして好きな位置へ {#drag}

[cockpit roster](basics.html) はこれまで1段ずつしか並べ替えられませんでした。行の ⋮ メニューも
タイルの ◀▶ も隣と入れ替えるだけなので、長いリストの端から端へ動かすには同じ操作を何度も押す必要が
ありました。各行に**ドラッグハンドル**が付き、任意の位置にドロップできます。

### 有効にする

**手動ソートのときだけ**出ます。手で置いた行がそのまま留まるのはこのモードだけだからです
（`auto` と `priority` はセルの状態が変わるたびに順序を計算し直すので、ドラッグした配置は次の
再計算で消えます）。

ツールバーのソートボタンを **manual** になるまでクリックしてください。各行にハンドルが出るので、
掴んで好きな位置にドロップします。

- ⋮ メニューとタイルの ◀▶ は**そのまま使えます** — 置き換えではなく、追加のジェスチャーです。
- **キーボードからの経路は引き続き ⋮ メニュー**です。ドラッグはキーボードでは行えません。
- 順序は1本のフラットなリストなので、タイル表示のグリッドもロスターと一緒に並び替わります。

## 2. roster の `summary` 行がすべてのエージェントで埋まる {#summary}

**設定は不要です。**

この行は Claude のセル以外では空でした。表示していたのは Claude Code が自分で書いたタイトルで、
他のエージェントは同等のものを書きません。そのため codex / cursor / Antigravity / grok / copilot /
muse の行では、「このセルは何についてのものか」の答えが空欄のままでした。

各エージェントが**自分のストア**から答えるようになりました。履歴一覧に出るのと同じラベルです:

| エージェント | この行に出るもの |
|---|---|
| Claude | Claude Code が自分で書いたタイトル |
| codex / cursor / Antigravity / grok | そのセッションを開いたときのプロンプト |
| copilot / muse | エージェント自身の要約（会話の進行につれて書き換わります） |

そのエージェントがまだ何も書いていない行は、これまでどおり空のままです。また、すぐ下の `prompt`
行を繰り返すだけになる場合（1ターンだけのセル）は、同じことを2回言わずに引っ込みます。

## 3. macOS の `Cmd+Shift+<英字>` — お使いの keymap を確認してください {#cmd-shift}

**これはすでに影響しているかもしれません。** 次のような設定は:

```text
{ "keymap": { "files-find": "Cmd+Shift+P" } }     ← 大文字 P: 読み込まれるが発火しない
```

読み込まれ、設定画面にも「割り当て済み」と出るのに、macOS では**決して発火しません**。Cmd を
押している間、Mac のブラウザはキーイベントに**シフトされていない**文字を入れるため、打鍵は `p`
として届き、設定は永遠に来ない `P` を待ち続けます。

直すのは**ファイル上の綴り**であって、押すキーではありません:

```json
{ "keymap": { "files-find": "Cmd+Shift+p" } }
```

物理的にはまったく同じ打鍵で、こちらは発火します。

- MulmoTerminal が起動時と `validateKeymap` で**警告する**ようになり、小文字の綴りを提示します。
- 警告は**意図的に致命的ではありません**。まったく同じ記述が Windows / Linux のブラウザでは正しく
  （そちらでは `Meta+Shift+P` が実際に `P` を報告します）、Linux ホストに Mac のブラウザから
  つなぐのはここでは普通の使い方で、サーバはどのブラウザが接続してくるかを知り得ないためです。
- マッチングは引き続き大文字小文字を区別します（`a` と `A` は別の打鍵）。他の設定のマッチングは
  何も変わりません。

### 確認のしかた

`~/.mulmoterminal/config.json` を開き、`Cmd`（または `Meta`）と `Shift` の両方を含む `keymap` の値を
見て、末尾が1文字の英字なら小文字にします。サーバを再起動すれば警告も消えます。

## このリリースのその他 {#also}

このリポジトリが配布する `keymap` サンプルは、CI で**実物のバリデータに通して解析**されるように
なりました（エラーだけでなく警告もビルドを落とします）。これが必要だったのは、ガイドが両言語とも
`Cmd+Shift+A` を読者に提示していたためです — 上の節で「macOS では死んでいる」と説明しているまさに
その綴りでした。リリースのチェックリストにはサンプル検証が最初から書かれていましたが、チェック
リストを実行するものが無かった、というだけの話です。
