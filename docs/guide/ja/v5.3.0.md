# 5.3.0 — ファイルの中を検索、そしてペインが「どこを見ていたか」を覚える

**5.3.0 時点のスナップショットです（リリース 2026-09-19）。** アプリが進めばこの記述は古くなります —
それは想定どおりで、生きたリファレンスは各節からリンクしているガイド本体です。

3つ入りました。設定が要るものはありません。1つ目は新機能、2つ目は手作業のリロードが1つ消える話、
3つ目は同じペインに対する小さな修理の束です。

## 1. 開いているプロジェクトの、ファイルの中を検索する

Files ペインは**ファイル名で**探せました。これからは**中身で**探せます。

**開き方**: セルを拡大（**⤢**）→ **フォルダ**ボタンで Files ペインを開く → ヘッダの**虫めがねに線が
入ったアイコン**を押す（ラベルは *Search in files*）。隣にある普通の虫めがねは、従来どおり「名前で探す」
ほうです。

**キーに割り当てることもできます。** アクション名は `files-search` で、ペインが閉じていれば**先に開いて
から**検索パネルを出します:

```json
{
  "keymap": {
    "files-search": "Cmd+Shift+f"
  }
}
```

これを `~/.mulmoterminal/config.json` に書いてサーバを再起動してください。**英字が小文字なのは意図的
です**: Cmd を押しているとき macOS のブラウザは shift の効いていない文字を報告するので、`Cmd+Shift+F`
のように大文字で綴ると**発火しません**。いまは起動時に警告が出ます — ついでに言うと、このリポジトリの
テストはこれらのページの設定サンプルを**実物のバリデータに通す**ので、このページの初稿にあった大文字も
そこで捕まりました。

**出てくるもの**: ファイルごとにまとめられた一致行と、いま選んでいる結果の前後の行。入力した語は
どの行でも強調されます。結果を選ぶとそのファイルが開き、**カーソルがその行に載ります**。

**何を検索して、何を飛ばすか:**

- クエリは既定で**リテラル**です。**正規表現**と**大文字小文字を区別**の2つのトグルがあります。
  どちらも切っているときは smart case — 小文字だけのクエリは大小どちらにも当たり、大文字を含むクエリは
  区別します。
- git リポジトリでは **`.gitignore` が効きます**。エージェントがさっき作ったファイルも検索対象です。
  git 管理下でなければ ignore ファイルは一切読みません。
- **未保存の編集があるファイルは、ディスクではなく画面の内容を検索します**（リテラル検索のとき）。
  正規表現トグルが入っているときは対象から外し、「保存してください」と表示します — 書きかけのパターンを
  画面の内容に対して走らせると固まり得るためです。どちらの場合も、そのファイルのディスク由来の古い
  一致は捨てます。

各オプションのリファレンスは[設定ガイドの keymap の節](config.html#keymap)にあります。

## 2. 開いている Markdown プレビューが、ファイルに追随する

いままで: エージェントが書いている `.md` を **Preview** で開いていても、新しい内容を見る手段は
ブラウザのリロードだけでした。

これからはプレビューが追随します。設定は不要です。編集しているセルの隣に plan や README を開いて
おく使い方をしているなら、**やらなくてよくなるリロード**がこれです。

## 3. Files ペインが「どこを見ていたか」を覚え、読み終える前に嘘をつかなくなる

同じペインへの修理が4つ。すべて自動です。

- **表示モードが戻ります。** `.md` を **Preview** で読んでいたなら、Preview のまま戻ります —
  ブラウザのリロード越しでも、ズームを別セルへ移して戻ってきたときでも。戻すのは**同じファイルに対して
  だけ**で、そのパスがまだサーバの描ける Markdown である場合だけです。そうでなければエディタで開きます。
- **見ていた場所が戻ります。** エディタの最上行、カーソルのあった行、そしてツリーのスクロール位置。
  **最上行はそれ自体が必要**でした — **スクロールではカーソルも選択も動かない**ので、クリックせずに
  読んでいる人は、そうしないと「読んでいた途中のファイルの先頭」に戻されてしまいます。エージェントが
  短くしたファイルで記憶した行が末尾を越えていたら、一番近い実在の行に着きます。
- **読み直しているあいだ、前回のツリーを描きます。** 一度開いたことのあるディレクトリなら、ペインを
  開いた瞬間にそのツリーが出て、サーバの返事が来たら差し替わります — 待っているあいだに展開した
  ディレクトリも畳まれません。
- **読み終える前に「空」と言わなくなりました。** まだ読んでいないディレクトリは `Loading…`、
  `Empty directory.` は「リストが空で返ってきた」という意味だけになりました。読み込みが失敗したときは、
  もう保証できないツリーではなくエラーを表示します。

## 入ったかどうかの見分け方

一度開いたことのあるプロジェクトで Files ペインを開いてください。`Loading…` の一瞬を挟まず、
**いきなりツリーが出ます**。長いファイルを開いて途中までスクロールし、ズームを別のセルへ移して戻ると、
**同じ行**にいます。

**アップグレード直後に一度だけ起きること**: まだ何も記憶されていないので、最初のリロードは先頭から
始まります。一度読んでからリロードすれば、そこに戻ってきます。
