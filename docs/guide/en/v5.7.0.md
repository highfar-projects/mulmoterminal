# 5.7.0 — A way back from history view, and phone rows that say what they are

**A snapshot as of 5.7.0 (released 2026-09-24).** It will go stale as the app moves on — that is
expected, and the living reference is the guide each section links to.

Nothing to configure. Both changes are on as soon as you run 5.7.0.

## A cell in copy-mode says so

**Nothing to turn on.**

Scroll a **shell** or **Codex** cell back with the mouse wheel, or drag in it, and tmux puts the
pane in **copy-mode**. Until now nothing said so: every key went to tmux instead of the program, so
under `mode-keys vi` `h` `j` `k` `l` moved a cursor and other letters simply vanished.

Now a banner appears under the cell's header:

> Viewing history — what you type doesn't reach the terminal. Press q to return.

with a **Back to input** button beside it. Either the button or `q` takes you back. Leaving sends
nothing to the program, and the terminal gets the focus back, so you can type straight away.

**How to tell you have it:** in a shell cell, scroll up with the wheel. The banner appears; click
**Back to input** and it goes away.

**What it does not do:** it does not stop the wheel from entering copy-mode in the first place, and
copy-mode's own keys (moving, selecting, copying) are unchanged. If you enter copy-mode from outside
the app — a separate `tmux attach` — the banner appears the next time you type into that cell.

Living guide: [Feature reference](features.html) (the "Leave history view" row).

## The phone's terminal list names what each session is

**Nothing to turn on.**

A running session with no session note and no AI title used to appear in the phone's terminal list
as its **UUID**. Now it is named from its conversation — the title the agent wrote, the latest
prompt, the first thing you asked — and a brand-new session by where it runs, such as
`mulmoterminal · codex`. The id appears only when there is nothing else to go on.

A session you `/clear`ed is not named after the conversation you ended.

Your session note still wins over everything else, and which sessions the list offers is unchanged.

**How to tell you have it:** open a new terminal and send it a first prompt before any title has
been generated. On the phone, its row shows that prompt instead of an id.

**Still to come on the phone side:** the host now also sends each row's latest prompt, and showing
it under the title — plus showing the directory by project name rather than a truncated absolute
path — is tracked in [mulmoserver#287](https://github.com/receptron/mulmoserver/issues/287).

Living guide: [From your phone](phone.html) ("What you see").
