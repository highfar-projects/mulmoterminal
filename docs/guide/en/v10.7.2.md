# 10.7.2 — End a worker and close its cell, and lighter worktrees on macOS

**A snapshot as of 10.7.2 (released 2026-10-16).** It will go stale as the app moves on — that is
expected, and the living reference is the guide each section links to.

## New features

### End a session and close its cell in one call

If you have an agent that starts worker sessions (`spawnBackgroundChat`) and replaces them as it goes,
it can now end a worker and make its cell go away too
([#3068](https://github.com/receptron/mulmoterminal/pull/3068),
[#3067](https://github.com/receptron/mulmoterminal/issues/3067)):

```
curl -X POST http://localhost:$MULMOTERMINAL_PORT/api/session/<id>/close
```

The answer is the same as `terminate`'s: `{"ok":true,"ended":true}`. The cell then closes, just as it
does when an agent ends with `/exit`, and the session is listed under Reopen.

Before this, the only way was `POST /api/session/:id/terminate`, which ended the session but left its
cell showing `[session ended]` until you clicked its close button — one dead cell per worker.

- `terminate` still leaves the cell. That is on purpose: a cell's own Restart and token switch use it
  and reconnect the same cell.
- The cell closes under the same rule as `/exit`. A worktree cell, or a cell ended within about two
  seconds of starting, keeps its `[session ended]` banner.

**How to tell it worked:** call `close` on a session that has had a cell open for a few seconds. The
cell disappears instead of showing `[session ended]`.

More: [Server API specification](https://github.com/receptron/mulmoterminal#server-api-specification) in the README.

## What looks different

Nothing on screen. The new route is for agents and scripts.

## Under the hood

- **On a Mac, your worktrees are no longer backed up by Time Machine**
  ([#3066](https://github.com/receptron/mulmoterminal/pull/3066),
  [#3059](https://github.com/receptron/mulmoterminal/issues/3059)). Worktrees are created and thrown
  away many times a day, each with tens of thousands of files once dependencies are installed.
  The first time MulmoTerminal creates a worktree, it excludes the folder that holds them all
  (`~/.mulmoterminal/worktrees`) from Time Machine and marks it for Spotlight not to index. Nothing
  needs doing. To back them up after all, run `tmutil removeexclusion ~/.mulmoterminal/worktrees`.
  More: [Worktrees → Where it lands](worktree.html#location).
- **A session you end is not picked up again later.** Ending a session through either route now
  stops it from appearing as a new cell the next time a grid opens
  ([#3068](https://github.com/receptron/mulmoterminal/pull/3068)).
