# 6.7.0 — Talk from the Tools menu, move terminals from the keyboard

**A snapshot as of 6.7.0 (released 2026-09-29).** It will go stale as the app moves on — that is
expected, and the living reference is the guide each section links to.

This release finishes the cell-header clean-up that 6.6.0 started. Nothing needs configuring except
the optional move keys below.

## Talk to another terminal is in the Tools menu

The `forum` button on a cell's second row is gone. Open the cell's **Tools** menu (the wrench on row 1)
and pick **Talk to another terminal…**, just above *Restart the agent*.

- The row is there **only while another terminal is open** to talk to. With one cell on screen it is
  simply absent — that is not a bug.
- It works from a tile as well as an enlarged cell.
- The panel it opens is the same as before — bring a terminal's last turn here, exchange one turn, or
  start a round table — and it now opens under the right end of row 1. The "exchanging — stop"
  control appears there too.

Living guide: [Making the cells talk to each other](conversation.html#start).

## Move a terminal from the keyboard or the command palette

Two new actions move the current terminal one place — left / right in the grid and the thumbnail strip,
up / down in the roster:

- `terminal-move-prev`
- `terminal-move-next`

"Current" is the enlarged terminal, or with nothing enlarged, the cell the cursor is in. They work in
**manual order only**; in auto or priority order the grid decides the position, so the key does
nothing there (a single-key binding falls through to the terminal) and the palette row says why.

They are listed in the command palette already. To bind keys, add them to `keymap` in
`~/.mulmoterminal/config.json` and restart the server:

```json
{
  "keymap": {
    "terminal-move-prev": "Alt+Shift+ArrowLeft",
    "terminal-move-next": "Alt+Shift+ArrowRight"
  }
}
```

How to tell it worked: switch the grid to **Manual** order (the ordering menu in the toolbar), put the
cursor in a cell and press the key — the cell swaps with its neighbour.

Living guide: [Keyboard shortcuts](config.html#keymap).

## Set aside has a new icon

The set-aside button is now a **person asleep in a bed**, in the cell header and in the roster /
thumbnail ⋮ menu. The crescent moon it replaces read as a dark-mode switch. Behaviour is unchanged.

Living guide: [Features](features.html).

## Tooltips in your language

A cell's tooltips and spoken labels now follow the UI language in all five languages, and so do those
of the launch form (directory chips, agent picker, worktree rows, resumable sessions), the side panes,
the full-screen views (collections, accounting, GitHub, rooms, wiki, shared apps) and the run, skill,
deck and round-table menus. The rest of the app follows in a later release.

## Blueprints: documents step by step

- After a document build finishes, **What to do next** offers the next step in the same folder —
  after *style*, *write* or *polish*; after *write*, *polish* — and opens the form already filled in.
- **Start from an example** groups the examples under the base they are built on (the document folder,
  Firebase, local).
- A question that asks for one item per line now has a multi-line field, and the lines survive editing.
- A question that lists files in the folder has **Pick from the folder**: click files in the list to
  add or remove them instead of typing their paths.
- The project folder field accepts `~/…`.

## Fix: closing a cell ends its program

On a machine without tmux (and for Run command cells), a program that ignored the hang-up signal
could keep running after its cell was closed. It is now killed after a short grace. Nothing to
configure; to check, close a cell and confirm its program is gone from `ps`.

Living guide: [Blueprints — documents](blueprints.html#documents).
