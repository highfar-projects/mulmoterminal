# 9.1.0 — Your agent writes Remotion scenes itself, and a terminal's files are one tap away on the phone

**A snapshot as of 9.1.0 (released 2026-10-07).** It will go stale as the app moves on — that is
expected, and the living reference is the guide each section links to.

## New features

### Your agent can write a Remotion scene itself

In 9.0.0 a `remotion` scene in a MulmoCast video was written by a separate Claude Code that the
server starts in the background. Now **the agent you are talking to in the cell can write the scene
itself** — it is given Remotion's rules along with the MulmoCast tool — so you can shape it together
in the conversation ([#2918](https://github.com/receptron/mulmoterminal/pull/2918)).

How to try it (the optional packages from [MulmoCast videos](mulmocast.html#remotion) must be
installed, as in 9.0.0):

1. Ask in a cell, for example *"make a short MulmoCast video; write the second beat yourself as a
   remotion component, and let's adjust it together"*.
2. The agent writes the component — usually a `.tsx` file next to the script, or inline — and puts it
   in the beat as `code`.
3. Make the movie from the GUI panel as usual. Ask for changes in words, and render again.

- Nothing is written in the background this way, so it does not use the server's Claude Code login,
  and you can see and edit the code.
- If the render stops with an error, show the error to the agent and it fixes the component.
- Asking for a scene to be "left to Claude Code" still works the 9.0.0 way (`prompt`).

The reference is [Pass a finished component instead](mulmocast.html#remotion-code).

### On the phone, a terminal opens its project's files

When a project shares files with the phone (`mobileFiles`, new in 9.0.0), **the phone's terminal
screen now shows a folder button** that opens that project's file list directly — no detour through
another section ([#2916](https://github.com/receptron/mulmoterminal/pull/2916)).

- The button appears only when the terminal's project shares files. A project that shares nothing
  shows no button, even when an enclosing folder shares some.
- From the file list, a back button returns to the terminal you came from.
- The Files icon in the phone's header has moved from beside Feeds to beside Issues, next to the
  terminals.

The phone side shipped with the current MulmoServer, so there is nothing to update there. How to
share files is in [Files the phone may open](config.html#mobile-files).

## What looks different

- On the phone, the header's Files icon sits with the terminals (beside Issues) rather than behind
  Collections ([#2916](https://github.com/receptron/mulmoterminal/pull/2916)).
- The [MulmoCast videos](mulmocast.html#remotion-code) guide now says to just ask the agent to write a
  scene, instead of pointing it at mulmocast's documentation
  ([#2918](https://github.com/receptron/mulmoterminal/pull/2918)).

## Under the hood

- Updated libraries: mulmocast 2.15.0, the MulmoCast panel 5.3.0 and the shared core 5.11.0
  ([#2918](https://github.com/receptron/mulmoterminal/pull/2918)). Nothing needs doing.
- The tool description an agent receives for MulmoCast is longer, because it now carries the Remotion
  rules in full.
- The ChangeLog records the phone change above
  ([#2917](https://github.com/receptron/mulmoterminal/pull/2917)).

**How to tell you have it:** ask the agent in a cell whether it can write a Remotion scene's `code`
itself — it can describe the `code` form and the rules without looking anything up.
