# 11.0.0 — Ask your data a question

**A snapshot as of 11.0.0 (released 2026-10-19).** It will go stale as the app moves on — that is
expected, and the living reference is the guide each section links to.

With this release, analysing data by conversation is complete: you hand the agent a file, ask what you
want to know, and get a spreadsheet with live formulas and charts that follow it. We checked it by
asking fifteen analysis questions the way anyone would — from "analyse this file" to "is B really
better than A?" and "who is likely to cancel?" — and fixed what that turned up
([#3113](https://github.com/receptron/mulmoterminal/issues/3113)).

## New features

### Ask a question, not only "analyse this"

You no longer need to say "analyse". Ask the question you have about the file
([#3114](https://github.com/receptron/mulmoterminal/pull/3114)):

> Can we say B did better than A in ab_test.csv?

> data/sensor.csv is one day of sensor readings. Is anything unusual?

> Forecast next month's sales from data/monthly_sales.csv.

The agent answers in words, and the answer comes with the spreadsheet and charts it is based on, so you
can check it and change it.

More: [How to ask](spreadsheet.html#analysis-how-to-ask).

### Excel files

An Excel file (`.xlsx`) works like a CSV
([#3114](https://github.com/receptron/mulmoterminal/pull/3114)). The agent tells you which worksheets the
file has and which one it read. A large Excel file is added up by a script.

More: [Analysing data from start to finish](spreadsheet.html#analysing-data-from-start-to-finish).

### New spreadsheet functions

`ROW`, `COLUMN`, `ROWS` and `COLUMNS` now work
([#3116](https://github.com/receptron/mulmoterminal/pull/3116)) — `=ROW()-1` numbers the rows of a data
sheet, for example. Before, they showed `#NAME?`.

More: [Functions you can use](spreadsheet.html#functions-you-can-use).

## What looks different

### The spreadsheet arrives without error cells

When a formula in the spreadsheet comes out as an error (`#N/A`, `#VALUE!`, …), the agent is now told
which cells, and fixes them before telling you the spreadsheet is ready
([#3114](https://github.com/receptron/mulmoterminal/pull/3114)). You may see it present the spreadsheet
twice while it does so. An error it leaves on purpose — a lookup that finds nothing, say — is one it
tells you about.

## Under the hood

### Months and text are read correctly

Nothing to do; the fixes apply to every spreadsheet, old and new
([#3116](https://github.com/receptron/mulmoterminal/pull/3116)).

- **A month written `2025-01` was read as the number 2025.** A monthly total built on such a column put
  the whole year's total in every month, and nothing showed an error. Now `2025-01` is text, and each
  month gets its own total.
- **Text with a comma (`Tokyo, Japan`) was read as 0.** It is now the text.
- **A sheet named in Japanese can be referred to without quotes**, as in `=基準!B1`.
- Sheets that refer to each other calculate correctly and quickly, and lookups over `$A$2:$C$10`
  ranges work ([#3114](https://github.com/receptron/mulmoterminal/pull/3114)).

**How to tell you have the fix:** in a spreadsheet, type `Tokyo, Japan` in A1 and `=LEN(A1)` in B1.
It shows 12. Before, it showed 1.

One thing still differs from Excel: `2025-01` is not turned into a date. Formulas that take a date
(`YEAR(A1)`) answer `#VALUE!` for it, and typing `2025-01` into a cell yourself is read as a
subtraction. Set the cell editor's type to **String** to keep it as written.
