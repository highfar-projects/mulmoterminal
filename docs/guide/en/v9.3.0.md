# 9.3.0 — Cells opened together are spread across your subscriptions

**A snapshot as of 9.3.0 (released 2026-10-08).** It will go stale as the app moves on — that is
expected, and the living reference is the guide each section links to.

## New features

Nothing to switch on in this release. If you use [token rotation](token-rotation.html), the one change
is below.

## What looks different

- **Cells opened together now start on different subscriptions.** Before, with several subscriptions
  registered, opening a few cells in a row could send every one of them to the same subscription, because
  the usage figures only move when they are re-read and each new cell made the same choice. A cell now
  weighs how many sessions are already running on a subscription: its room is divided by one plus that
  count, so the next cell goes to a less busy one. A subscription whose window is about to reset still
  gets the first cells ([#2927](https://github.com/receptron/mulmoterminal/pull/2927)).

  See it: open three cells one after another and look at each header. They name different subscriptions
  where before they named one. How it ranks is in [Token rotation](token-rotation.html).

## Under the hood

- Nothing changes unless you configure `tokenRotation`, and nothing needs doing.
- A session counts as running while this server holds its Claude process, so one detached long enough to
  be cleaned up no longer weighs on a subscription
  ([#2927](https://github.com/receptron/mulmoterminal/pull/2927)).
- Dependencies were brought up to date: MulmoCast and its types, the shared MulmoClaude packages, the
  router and the build tool ([#2930](https://github.com/receptron/mulmoterminal/pull/2930)).

**How to tell you have it:** with `tokenRotation` configured, open three new Claude cells in a row — their
headers name different subscriptions.
