# feat(blueprint): アプリを作り終えたら、使い始め方と動作確認の手順を完了画面に出す (#2479)

## 問題

「すべての工程が完了しました」のあと、どう使い始めればよいか分からない。完了画面に出るのは種類（usecase）の `report` だけで、アプリを作る種類（`product`、`internal`）には `report` が無い。起動のしかたは README にあるが、画面には出ない。

## 方針

- 土台（base）の manifest にも `report` を置けるようにする。
  - 出す報告は種類のものを優先し、無ければ土台のものにする。
  - 選び方は純粋な関数 `reportOf`（`common/blueprint/manifest.ts`）に切り出して試験する。
  - 土台の manifest が読めないときも、種類の報告はこれまでどおり出す。
- `local` と `firebase` の土台は `report: .blueprint/start-here.md`。最後の工程が書く。
  - `local`（handover）
    - 中身: 起動のしかたと開くアドレス、必須の機能ごとのチェックリスト（操作 → こうなれば OK）、データの場所、困ったとき。
    - 判定 `handover.sh`: `yarn start`、`http://localhost:`、`- [ ]` の行があること。
  - `firebase`（deploy-production）
    - 中身: 本番の URL とログイン、チェックリスト（断られるべき人が断られることも含む）、次に直すときの手順（開発用 → 本番）、費用と安全。
    - 判定 `start-here.sh`: 本番の URL と `- [ ]` の行があること。
- 完了画面では、報告を「すべての工程が完了しました」のすぐ下に移す。変わったファイルの一覧より上にする。
- 試験
  - `packs.spec.ts`: web 系の土台が `start-here.md` を名指しすること、土台の報告をその土台の判定が確かめていること。

## 範囲外

- エージェントが実際に書く中身の出来は、ビルドを一本通さないと確かめられない。
