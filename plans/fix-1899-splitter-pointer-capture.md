# fix: 分割バーのドラッグを iframe に奪われないようにする (#1899)

> **この文書の読み方 —— 時系列のログであって、現状の仕様書ではない。**
> 現在のコードの仕様はコードが唯一の情報源。数値は sha に紐づけて書くこと。

## 症状

拡大セルの横にある分割バーをドラッグすると、**ポインタが隣のペインの iframe に乗った瞬間に
追随が止まり、ボタンを離しても終わらない**。離した後にマウスを動かすと、ボタンを押していないのに
ペインの幅が変わり続ける。

## 原因

`dragSplitter`（当時は `src/components/TerminalGrid.vue` 内）が `window` に `pointermove` /
`pointerup` を張るだけで、**ポインタをキャプチャしていなかった**。

ポインタイベントはカーソル直下の要素に配送され、**iframe の中で起きたものは親ドキュメントに一切
届かない**（`window` の capture フェーズでも届かない）。したがってカーソルが iframe に乗ると:

- `pointermove` が来ない → 幅が固まる
- `pointerup` が来ない → `onUp` が走らず、**リスナーが張られたまま**になる

その後カーソルが親ドキュメントに戻ると `pointermove` が再開し、**ボタンを離しているのに
リサイズが続く**。

## なぜ「たまにしか起きない」ように見えるか（再現の要点）

**セパレータはポインタに 1:1 で追随するので、幅が自由な間はカーソルの下に居続ける。** 実際、
小刻みに動かすドラッグでは `elementFromPoint` は最後まで `DIV.w-[5px]`（セパレータ自身）を返し、
**iframe には一度も乗らない**。最初の再現試行が「再現せず」になったのはこれが理由で、
`elementFromPoint` を各ステップで記録して初めて分かった。

カーソルが iframe に到達するのは、**セパレータが追いつけないとき**の 2 つだけ:

1. **速いドラッグ** —— 1 回の移動量がセパレータから iframe までの距離を超える
2. **幅が下限に張り付いた後** —— セパレータが止まり、カーソルだけが進む

Files ペインには iframe の左にファイル一覧の列があるので上記が要る。一方
`SharedAppPreview`（issue が名指ししている画面）は iframe がセパレータのすぐ隣なので、
**距離がほぼ 0 = 最初の 1 移動で乗る**。issue の「ほとんど動かない」はこの形。

## 修正

`pointerdown` でセパレータに `setPointerCapture` する。キャプチャ中はそのポインタのイベントが
**カーソルが何の上を通ろうとセパレータに再ターゲットされる**ので、`window` のリスナーに届く。

`pointercancel` でも終了させる —— **キャプチャ中のポインタがキャンセルされると `pointerup` は
飛んでこない**ので、これが無いと同じ形でドラッグが取り残される。

**このドラッグを操れるのはこのポインタだけ**にした（`pointerId` で `pointermove` /
`pointerup` / `pointercancel` を選別）。2 本目のタッチやペンは別ポインタで、そのイベントも
`window` に上がってくる。**`pointercancel` を購読したこと自体がこれを到達可能にする** ——
ブラウザは自分のスクロール判定で無関係な指をキャンセルするので、選別が無いと
「ユーザーがまだドラッグ中なのに終了する」経路が新しく生まれる。

**1 本のセパレータで同時に走るドラッグは 1 つだけ**にした。同じ 5px のバーへの 2 回目の
`pointerdown`（2 本目の指、タッチの上のペン）は、それまで別々の原点を持つ 2 つのクロージャを
開き、互いの基準で幅を書き合い、それぞれが離されたときに保存していた。**新しい press が
引き継ぐ**形にしてある —— 無視する形にすると、終了イベントが届かなかったドラッグが
セパレータを永久に死なせるので、いま直しているバグより悪い失敗になる。

あわせて `dragSplitter` を `src/composables/dragSplitter.ts` へ切り出した。バグの規則を
それ自身のファイルの関数にしてテスト可能にするため（`remember` だけ注入）。**本体は逐語で移動**。

## jsdom には pointer capture が無い

`setPointerCapture` / `releasePointerCapture` / `hasPointerCapture` すべて `undefined`
（`el.setPointerCapture is not a function`）。なので spec 側でセパレータに実装を持たせている。
**アプリ側にフォールバックは入れていない** —— 対象ブラウザはすべて対応しており、テスト環境の
欠落をアプリのコードで回避するのは筋が違うため。分割バーに `pointerdown` を撃つ既存 spec は無い
（確認済み）。
