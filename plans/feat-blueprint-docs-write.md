# 文書の設計図パック（2）: 作る

issue: #2303（前段は #2301 の「規約をつくる」）

## 何のためか

非エンジニアが「こういう文書がほしい」と言えば、そのフォルダの規約に沿った文書ができあがる。
記事一本から本一冊まで。長いものは部分（章）に分けて一つずつ書き、部分ごとに機械で確かめる。

## 決めたこと

- **書くのは Claude Code、確かめるのは chaff。** 部分を書くたびに chaff をかけ、規約で指摘が出ないことを確かめる。
- **規約は「規約をつくる」パックが残したものを使う。** `chaff.yaml` と `STYLE.md` があればそれに沿う。無ければ、ヒアリングで「chaff の既定で書く」を選んだときだけ進む。
- **事実は資料から取り、取ったことを引用で示す。** 資料を渡されたら `.blueprint/sources/` に集め、部分の中で資料から取った文は `.blueprint/citations/<部分>.json` に引用として残す。引用は `chaff cite` で原文にあることを確かめる。資料に無いことを事実として書かない。
- **人のファイルを上書きしない。** 構成で決めた出力ファイルが、構成を決めた時点ですでにあれば止める。
- **長い文書は部分ごとに繰り返す。** 構成（`outline.json`）の部分を一つずつ書き、書き終えた部分を `done` にする。残りがある限り次の回が始まる（`repeatWhile`）。

## パックの形（用途 `write`、土台は `docs`）

ヒアリング: 種類、何について、誰に・何のために、必ず入れること、資料（任意）、長さ、どの規約で書くか。

| 段 | 何をする | 検査 |
| --- | --- | --- |
| `brief` | 要旨（目的・読者・要点・資料から取る事実）を `.blueprint/brief.md` に。資料を集める | `checks/brief.mjs`: 要旨の節に中身がある、資料が揃っている、規約を使うなら規約がある |
| `outline` | 部分ごとのファイル・要点・長さを `.blueprint/outline.json` に | `checks/parts.mjs outline`: 形が正しい、出力ファイルがまだ無い |
| `draft` | 部分を一つずつ書く（繰り返し） | `checks/parts.mjs progress`: 書き終えた部分が増えた、その部分が chaff で指摘されない、引用が原文にある |
| `report` | 書いたもの、確かめたこと、確かめきれなかったこと | `checks/report.mjs` |

承認は `outline` の前（要旨の確認）と `draft` の前（構成の確認）。

## 確かめ方

- パックの定義は `packs.spec.ts` で読めること。
- 検査は偽の chaff で両方向を試験し、判定を壊して赤になることを確かめる。
- 実際に一度、規約をつくったフォルダで文書を書かせる。
