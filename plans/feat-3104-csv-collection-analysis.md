# 大きな CSV はコレクションで集計してから分析する（#3104）

構想 #3090 の案 4。`mulmoterminal-data-analysis` の「1. ファイルを読む」に「A large file」を足し、ガイド（en/ja）に「大きなファイル」を足す。

## 決めたこと（#3104 の推奨案）

- 5,000 行くらいまではこれまでどおりファイルを直接読む。それを超えたらコレクションで集計する（`getItems` と一覧が 5,000 行で止まるのと揃えた）。
- 集計の結果は値としてシートに入れ、集計したものだと書く。統計（相関・分位など）は、その表の上の計算式で出す。
- コレクションはスキルが自分で作る（`schemaDocs` の CSV の節に従う）。ファイルはワークスペースかプロジェクトの中に必要。外にあれば `data/` へのコピーを聞く。
- `manageCollection` が無いセルでは、スクリプトでファイルを流し読みして集計する。
- 全部の行が要る統計（全注文の中央値など）は `queryItems` では出ないので、流し読みのスクリプトで出すか、集計した表についての値だと言う。
- 分析をスキルとして残すときは、コレクションは持たず、次のファイルにコレクションを作る手順と、`queryItems` の問い合わせを全部書く。

## 確かめたこと

隔離した HOME で立てたサーバーに、MCP で直接呼んだ。

- 合成した 50,000 行の注文 CSV にコレクションを定義し、`queryItems` で全体、1 月（`where` の `gte` / `lt`）、店ごとを集計した。どれも別に書いた Node の集計と一致した。
- 主キーに重複がある CSV でも、`queryItems` は全部の行を数える（一覧は主キーごとに 1 行）。
- `groupBy` は列名だけで式は取れない。月ごとは `where` で月ごとに問い合わせる、と手順に書いた。
- パラメータは `query` の下に入れる（入れないと拒否される）。手順の例をその形にした。
- `limit` は 10,000 を超えると拒否される。
- 集計した表を `presentSpreadsheet` に値として出し、その上に計算式（合計・平均・`CORREL`・`MEDIAN`）を置き、`source` 付きの `presentChart` を出せた。

エージェントが自分からこの手順に従うかは、まだ試していない（`claude -p` の上限が戻ってから試す）。
