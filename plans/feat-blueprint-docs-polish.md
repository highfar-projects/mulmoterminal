# 文書の設計図パック（3）: 整える

issue: #2305（前段は #2301 の「規約をつくる」、#2303 の「作る」）

## 何のためか

すでにある文書（リポジトリの docs、手順書のフォルダ）を、規約に合わせて一つずつ整える。
**書いてあることは変えない。** 変えてよいのは言い回しで、何を言っているか・どこを指しているかは変えない。

## 決めたこと

- **意味を守る検査を機械でする。** 整えた文書ごとに、`.blueprint/originals/` に残した原本と比べ、次が一つでも変わっていれば落とす。
  - 見出し（順番も一字一句も。ほかの文書がリンクしている）
  - chaff の木の番地（条・節・項。「第3条第2項」「Section 4.2」がまだ同じ所を指すように）
  - コードブロック（一文字も）
  - リンク先（Markdown のリンクと、地の文の URL）
- **整えた後、規約で chaff の指摘が出ないこと。** 意味を変えずに直せない指摘は、直さずに報告に残す。
- **原本を残す。** 人がいつでも元に戻せるように。git のリポジトリなら `git diff` でも見られる。
- **一覧は測り直す。** 調べた段で書いた「直す前の指摘の数」を、chaff で測り直して照合する。
- **自分で走らせる確認は `verify`。** `progress` は回の終わりの本番の検査で、済んだ数を記録するので、途中で走らせると本番が落ちる（「作る」パックの実行で見つけた穴）。

## パックの形（用途 `polish`、土台は `docs`）

| 段 | 何をする | 検査 |
| --- | --- | --- |
| `survey` | 対象を測り、整える文書を選ぶ（上限の数まで） | `targets.mjs survey` |
| `polish` | 一つずつ整える（繰り返し）。承認の後 | `targets.mjs progress` |
| `report` | 整えたもの、確かめたこと、直さずに残したもの | `report.mjs` |
