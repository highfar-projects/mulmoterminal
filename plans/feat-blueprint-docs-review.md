# 文書の設計図パック（4）: 読み解く

issue: #2308（前段は #2301 規約をつくる、#2303 作る、整える）

## 何のためか

大きな契約書や規程を渡すと、食い違い・参照切れ・あいまいな所を、原文の引用付きで指摘し、直し方の案まで出す。
原本には手を付けない。

## 決めたこと

- **機械で見つかるものは機械に任せ、漏らさない。** chaff の構造の規則（`dangling-reference`、`numbering-gap`、
  `duplicate-definition`、`--experimental`）が出したものは、指摘にするか、理由を付けて退けるか、どちらかにする。
  chaff が出していない結果を「機械の結果」と名乗ることも許さない。
- **読んで見つけるもの（矛盾・あいまい・抜け）は Claude Code が書き、根拠は引用で示す。** 引用はすべて
  `chaff cite` で原文にあることを確かめる。引用できない指摘は指摘にしない。引用の検査は土台の
  `quotationProblems` を「作る」パックと共用する。
- **原本は変えない。** 読む段で文書の指紋を記録し、直し方の段で一致を確かめる。直した文書は
  `<名前>.proposed<拡張子>` として隣に置き、構造の不備が原本より増えていないことを確かめる。
- **直し方まで出すかはヒアリングで選ぶ。** 「指摘だけ」なら直し方の段は原本が変わっていないことだけを見る。

## パックの形（用途 `review`、土台は `docs`）

ヒアリング: 文書（1 行に 1 つ）、種類、特に気になること（任意）、どこまで進めるか。

| 段 | 何をする | 検査 |
| --- | --- | --- |
| `read` | 構造の不備をすべて扱い、読んで食い違いを探し、`.blueprint/findings.json` に書く | `checks/findings.mjs read` |
| `propose`（承認の後） | 指摘ごとに直し方を書き、直した文書を別ファイルに作る | `checks/findings.mjs propose` |
| `report` | 見つけたこと、確かめたこと、確かめきれなかったこと | `checks/report.mjs` |

## 確かめ方

- 検査は偽の chaff で両方向を試験し、判定を一つずつ壊して赤になることを確かめる。
- 実際に一度、食い違いを仕込んだ契約書で読み解かせる。
